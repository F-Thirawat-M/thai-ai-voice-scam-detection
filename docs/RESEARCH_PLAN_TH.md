# แผนข้อมูลและการทดลอง: AASIST และ RawNet2 สำหรับเสียงไทย

> **เอกสารแผนเดิม:** ทิศทางล่าสุดเปลี่ยนมาใช้ Common Voice + เสียง TTS เป็นแกนหลัก ให้อ่าน [Workflow หลักฉบับใหม่](COMMON_VOICE_PROJECT_WORKFLOW_TH.md) ก่อนลงมือ แผน SEA-Spoof และชุดเสริมในไฟล์นี้เก็บไว้เป็นประวัติการวางแผน ไม่ใช่คำสั่งให้เริ่มงานใหม่ตามขอบเขตเดิม

วันที่จัดทำ: 30 กันยายน 2026

สถานะ: ข้อเสนอสำหรับคุยกับอาจารย์ ยังไม่ใช่ผลประเมินโมเดลหรือขอบเขตที่อาจารย์อนุมัติ

## 1. ข้อเสนอที่ควรใช้

เก็บ SEA-Spoof ภาษาไทยเป็นชุดหลักสำหรับการจำแนกเสียงจริง/ปลอม และตรวจชุดเสียงจริงที่มีข้อมูลประชากรเพื่อใช้เป็นชุดทดสอบเสริม งานหลักยังเป็นการเปรียบเทียบ AASIST กับ RawNet2 ส่วนอายุ เพศ และถิ่นใช้วิเคราะห์ความครอบคลุมและความผิดพลาดของโมเดล ไม่จำเป็นต้องเป็นข้อมูลป้อนเข้าโมเดล

ยังไม่ต้องเก็บเสียงใหม่ทั้งหมด ให้ตรวจ metadata ต้นทางก่อน หากกลุ่มเป้าหมายที่อาจารย์กำหนดไม่มีข้อมูลเพียงพอจึงเก็บเพิ่มเฉพาะส่วนที่ขาด จำนวนคลิปมากไม่ได้แปลว่ามีผู้พูดหลากหลาย ต้องนับผู้พูดไม่ซ้ำควบคู่กัน

## 2. ขอบเขตโครงงานฉบับร่าง

ชื่อที่เสนอ: การเปรียบเทียบ AASIST และ RawNet2 สำหรับตรวจจับเสียงสังเคราะห์ภาษาไทยภายใต้ช่องสัญญาณโทรศัพท์จำลอง

คำถามวิจัยหลัก:

1. โมเดล pretrained ทั้งสองตรวจจับเสียงสังเคราะห์ใน SEA-Spoof ภาษาไทยได้ดีเพียงใด?
2. ช่องสัญญาณโทรศัพท์จำลองและเสียงรบกวนทำให้ผลเปลี่ยนไปเท่าไร?
3. การ fine-tune ด้วยภาษาไทยและเสียงหลายสภาพช่วยให้ผลดีขึ้นหรือไม่?
4. เมื่อใช้เกณฑ์ตัดสินที่กำหนดไว้แล้ว เสียงมนุษย์ในชุดทดสอบเสริมแต่ละกลุ่มถูกทายเป็นเสียงปลอมมากน้อยเพียงใด?

ขอบเขตเสียงและผลลัพธ์:

- รับไฟล์เสียงพูดและให้คะแนนสนับสนุนว่าเป็นเสียงจริงหรือเสียงสังเคราะห์ พร้อมผลสองประเภท
- ชุดหลักเลือก `language=th` ตาม split เดิมของ SEA-Spoof ชื่อนี้เพียงอย่างเดียวไม่ได้ยืนยันสำเนียงหรือภูมิลำเนาของทุกไฟล์
- เสียงเข้าโมเดลเป็น mono 16 kHz; baseline แรกใช้ 64,600 samples หรือ 4.0375 วินาทีแรกต่อไฟล์ เสียงสั้นใช้ repeat padding ตามโค้ดปัจจุบัน บันทึกไฟล์ที่ถูกตัดหรือเติมซ้ำ
- หากทดลองหลายช่วง ให้เพิ่มวิธีเดียวกันสำหรับทั้งสองโมเดลและบันทึกเป็นการทดลองแยก ปัจจุบัน `--all-chunks` มีเฉพาะ RawNet2
- เงื่อนไขที่เสนอ: ต้นฉบับ, G.711 narrowband จำลอง, และ G.711 ร่วมกับ noise ที่ SNR 10/5 dB ต้องกำหนดลำดับประมวลผล ชนิด codec แหล่ง noise และ seed ก่อนทดลอง
- คำว่า `clean` ในโครงการหมายถึงไฟล์ต้นฉบับก่อนเพิ่มความเสื่อม ไม่ได้รับรองว่าไฟล์ทุกไฟล์ปราศจาก noise
- ผลจากช่องสัญญาณจำลองยังไม่ใช่หลักฐานว่าครอบคลุมเครือข่ายมือถือ/VoIP ทุกแบบ หรือการใช้งานสด
- ผลจำแนกเสียงสังเคราะห์ไม่ได้บอกว่าเจ้าของเสียงเป็นมิจฉาชีพหรือเนื้อหาที่พูดเป็นการหลอกลวง
- ชุดเสริมภาษาอีสานให้ระบุเป็นการทดลองภาษาอีสานโดยเฉพาะ ไม่เหมารวมว่าครอบคลุมทุกภาค
- ไม่มีการระบุอัตลักษณ์บุคคลหรือทำนายอายุ/เพศจากเสียงในขอบเขตนี้

## 3. ข้อมูลที่มีในเครื่อง

ตรวจจาก `data/manifests/thai_dev.csv` และ `thai_test.csv` ด้วย `scripts/audit_dataset_metadata.py`

| ชุด | จำนวนไฟล์ | เสียงจริง | เสียงปลอม | หน้าที่ |
|---|---:|---:|---:|---|
| Thai Dev | 9,904 | 3,216 | 6,688 | เลือก checkpoint/threshold และตัดสินใจเกี่ยวกับวิธีทดลอง |
| Thai Test | 9,903 | 3,216 | 6,687 | ประเมินตาม protocol ที่ล็อกแล้ว |
| Thai Train | ยังไม่มี manifest/Parquet ในโครงการ | - | - | ต้องเตรียมก่อน fine-tune |

เสียงจริงในแต่ละชุดมี metadata `source_dataset` เป็น `common_voice` 1,608 ไฟล์ และ `dialect_central` 1,608 ไฟล์ ไม่มีคอลัมน์อายุ/เพศ และช่อง `speaker_or_voice` ของเสียงจริงว่างทั้งหมด จึงยังยืนยันจำนวนผู้พูดไม่ซ้ำหรือการแยกผู้พูดข้าม split ไม่ได้ แม้เราจะรักษา split ทางการไว้แล้ว

ผลตรวจไฟล์เสียงจากรอบก่อน: Dev 12.67 ชั่วโมง ความยาว 0.59–68.69 วินาที; Test 12.93 ชั่วโมง ความยาว 0.66–33.62 วินาที; ทั้งสองมีมัธยฐานประมาณ 4 วินาทีและเป็น mono 16 kHz ข้อมูลนี้เป็นสถิติคุณสมบัติไฟล์ ไม่ได้ใช้ผลโมเดลบน Test เพื่อเลือกวิธีทดลอง

งานเตรียม metadata ไม่ได้ทำให้ได้ผล baseline โดยอัตโนมัติ ขณะจัดทำแผนยังมีเพียงผล smoke test ใน `results/` และยังไม่ได้ fine-tune

## 4. การเลือกชุดเสริม

### Common Voice Thai 27.0

แหล่ง: https://mozilladatacollective.com/datasets/cmu5x5tj000f2nq0755h8qcy5

หน้าเผยแพร่ระบุ 366,656 คลิป/7,997 ผู้พูด มี `client_id`, `age`, `gender`, `accents` แต่ข้อมูลบางส่วนขาดหาย และตัวเลขผู้พูดรายกลุ่มกับสรุป coverage บนหน้าเดียวกันไม่สอดคล้องกัน จึงยังไม่ใช้เป็นสถิติประชากรยืนยันของโครงงาน ต้องตรวจ TSV จริง โดยเริ่มจากเสียง validated และนับจุดตัดของฟิลด์ที่ครบ ไม่ถือว่าข้อมูลทุกคลิปมีอายุ/เพศ/ถิ่นพร้อมกัน

รอบนี้ตรวจได้เฉพาะเอกสารสาธารณะ ยังไม่ได้ดาวน์โหลด TSV หรือเสียง Common Voice จึงยังไม่มีจำนวนชุดที่ผ่านเกณฑ์คัดจริง ไม่ใช้รุ่น 27 เป็นหลักฐานว่าตรงกับรุ่นที่ SEA-Spoof ใช้ ต้องถามรุ่นและ mapping จากผู้สร้าง SEA-Spoof ก่อน

### Typhoon Thai Dialect Isan

แหล่ง: https://huggingface.co/datasets/typhoon-ai/thai-dialect-isan-dataset

เหมาะเป็นตัวเลือกสำหรับชุดทดสอบเสริมภาษาอีสาน มี age, gender, province และ district โดยจังหวัด/อำเภอตามคำอธิบายหมายถึงที่อาศัย ไม่ใช่จังหวัดเกิดหรือสำเนียงที่ตรวจยืนยันแล้วทุกคลิป

ตรวจเฉพาะคอลัมน์ metadata ใน Parquet ต้นทางด้วย byte-range requests และตรึง revision ระหว่างตรวจ โดยไม่บันทึกไฟล์เสียง ผลรวมอยู่ใน `results/dataset_metadata_audit.json` รหัสผู้พูดที่สคริปต์นับสกัดจากส่วนที่สามของชื่อไฟล์ เช่น `f_011` เป็น candidate speaker key ที่ต้องยืนยันความหมายกับผู้สร้างก่อนใช้เป็นจำนวนบุคคลแน่นอน

หน้า dataset แสดง Apache-2.0 ในหัวหน้า แต่เนื้อหา card ระบุ CC-BY-4.0 ต้องตรวจเงื่อนไขที่ผู้สร้างยืนยันก่อนนำเสียงมาใช้งานจริง

ตารางรหัสผู้พูดเป็นการนับจาก filename ไม่ใช่การยืนยันจำนวนบุคคล รหัสที่อายุขัดแย้งต้องสอบทานว่าเป็นการบันทึกหลายเวลา ความผิดพลาด หรือความหมายของรหัสอื่น ห้ามเลือกค่าอายุหนึ่งเองก่อนทราบสาเหตุ

ข้อเสนอหลังเห็นตัวเลข: ใช้เป็นตัวเลือกชุดทดสอบเสริมภาษาอีสานเชิงสำรวจ เก็บ x/unknown ไว้รายงานแยก สอบทาน 9 รหัสก่อนวิเคราะห์รายอายุ และไม่อ้างว่ารองรับทุกวัย/ทุกภาค หากใช้ Train กับ Test ของ Typhoon เพื่อฝึกและวัดผล ต้องแก้ปัญหารหัสผู้พูดซ้ำก่อน; หากนำมาใช้เป็นชุดทดสอบภายนอกอย่างเดียว ต้องประกาศชัดว่าทุกไฟล์ที่ใช้ไม่เข้าการฝึกหรือเลือก threshold และคำนวณผลระดับผู้พูดร่วมด้วย

การตัดสินใจเบื้องต้น:

- SEA-Spoof: คงเป็นชุดหลัก และขอรายละเอียด metadata/การแยกผู้พูดจากต้นทาง
- Typhoon Isan: ผ่านด้านการมีข้อมูลประชากรจำนวนมากพอให้สำรวจ แต่ยังมีประเด็นอายุขัดแย้ง ความหมายรหัส เงื่อนไขการใช้ และกลุ่มผู้สูงอายุน้อย จึงยังไม่เลือกเป็นหลักฐานความครอบคลุมทุกประชากร
- Common Voice: เป็นตัวเลือกถัดไปสำหรับตรวจ TSV จริง โดยยังไม่กำหนดจำนวนดาวน์โหลดหรืออ้างความครบถ้วนรายกลุ่มจาก card
- เก็บเอง: ทำเมื่ออาจารย์ยืนยันว่าต้องครอบคลุมกลุ่มที่ข้อมูลสาธารณะยังขาด และกำหนดเป้าหมายจำนวนผู้พูด/วิธีเก็บร่วมกันแล้ว

## 5. วิธีเตรียมชุดประชากรสำหรับทดสอบเสริม

1. ตรวจรหัสผู้พูด ค่าว่าง ค่าอายุผิดรูปแบบ และความขัดแย้งภายในผู้พูดเดียวกัน เก็บ `unknown`/`unspecified` แยกไว้
2. อายุ เพศ และที่อยู่ให้ใช้ตาม metadata ที่เผยแพร่ บันทึกวิธีเก็บหากผู้สร้างระบุ ไม่ทำนายแทนข้อมูลที่หาย
3. เสนอช่วงอายุเริ่มต้น <18, 18–29, 30–44, 45–59, 60+ เป็นช่วงสำหรับสำรวจ ไม่ใช่ข้ออ้างว่าครอบคลุมทุกช่วง ต้องปรับแผนก่อนเห็นคะแนนโมเดล หากข้อมูลขาดกลุ่มใดให้แจ้งตรง ๆ
4. รายงานจำนวนคลิป จำนวนผู้พูด และชั่วโมงต่อกลุ่ม ตรวจจุดตัดอายุ×เพศ×ถิ่นเพื่อดูช่องว่าง แต่ไม่บังคับรายงานผลเชิงเปรียบเทียบทุกจุดตัดที่มีตัวอย่างน้อย
5. ใช้ข้อมูลเสริมเพื่อทดสอบอย่างเดียวในรอบแรก เลือกจากเกณฑ์ metadata/คุณภาพเสียงก่อนดูคะแนน และบันทึกรายการคัดไว้ ไม่ใช้เพื่อปรับ threshold
6. ตรวจ overlap กับข้อมูลที่ใช้ฝึก หากยังตรวจ speaker overlap กับ SEA-Spoof ไม่ได้ ให้ระบุว่าไม่ยืนยันการแยกผู้พูดอย่างสมบูรณ์
7. รายงานทั้งอัตราผิดพลาดระดับคลิปและค่าเฉลี่ยระดับผู้พูด เพื่อลดอิทธิพลของคนที่มีคลิปจำนวนมาก ใช้ช่วงความไม่แน่นอนโดยสุ่มซ้ำระดับผู้พูดเมื่อรหัสผู้พูดเชื่อถือได้
8. หากต้องใช้ชุดเสริมฝึกในภายหลัง ต้องออกแบบการแบ่งผู้พูดใหม่สำหรับชุดเสริมและกันชุดทดสอบไว้ก่อน ไม่ใช้คนเดียวกันข้าม Train/Dev/Test

ชุดเสริมเสียงจริงวัดอัตราเสียงจริงถูกตัดสินเป็นปลอม (FRR) ที่ threshold จาก SEA-Spoof Dev ของแต่ละโมเดลได้ แต่ยังไม่ให้ EER รายกลุ่ม เพราะไม่มีเสียงปลอมของกลุ่มที่นิยามสอดคล้องกัน เสียง TTS ไม่ได้รับอายุ/เพศ/ภูมิลำเนาของคนอ่านต้นฉบับโดยอัตโนมัติ

## 6. ลำดับลงมือและสิ่งที่ต้องผ่าน

| ลำดับ | งาน | สิ่งที่ต้องได้ก่อนขั้นถัดไป |
|---|---|---|
| 1 | นำขอบเขตและผล audit ไปคุยอาจารย์ | ระบุว่าต้องครอบคลุมทุกภาค/วัยหรือยอมรับชุดที่มีข้อจำกัด และตกลงบทบาทชุดเสริม |
| 2 | ขอ mapping/รุ่นข้อมูลต้นทาง SEA-Spoof; ตรวจ metadata ชุดเสริม | หลักฐานรหัสผู้พูด/ประชากรและรายการสิ่งที่ยังยืนยันไม่ได้ |
| 3 | เตรียม protocol ร่วมกัน | dataset version, split, crop/padding, resampling, label, score direction และ seed ตรงกัน |
| 4 | ปรับตัวประเมินและตรวจด้วย Dev | บันทึก threshold แยกจาก Dev แล้วรับ threshold เดิมเมื่อประเมิน Test/ชุดเสริม |
| 5 | รัน pretrained บน Dev และจัดการข้อผิดพลาดของ pipeline | scores ครบทุกไฟล์ มี log และไม่มีการปรับวิธีจากผล Test |
| 6 | สร้างเสียงโทรศัพท์จำลองและเตรียม Thai Train | เงื่อนไขเดียวกันต่อไฟล์ต้นฉบับ ไม่มีไฟล์ดัดแปลงข้าม split |
| 7 | ทดลอง Thai-clean fine-tune แล้ว multi-condition หากเวลาเพียงพอ | เลือก checkpoint/ค่าตั้งจาก Dev บันทึก seed และเวลาฝึก |
| 8 | ล็อกการทดลองแล้วประเมินทุกระบบบน Test | EER ของ Test เป็นสถิติวัดผล; FRR/FAR ที่ใช้ตัดสินจริงต้องใช้ threshold ที่เลือกจาก Dev |
| 9 | ประเมินชุดเสริมตาม protocol เดิม | FRR รายกลุ่มพร้อมจำนวนคลิป/ผู้พูดและข้อจำกัด ไม่ใช้ผลกลับมาปรับโมเดลในรอบเดียวกัน |
| 10 | สรุปและเขียนรายงาน | ผลเทียบสองโมเดลทั้งคุณภาพ เวลา RAM/VRAM และขอบเขตการอ้างอิง |

ข้อที่พบในโค้ดปัจจุบันและต้องแก้ก่อนผลทางการ:

- `calculate_metrics` เลือก threshold จากชุดที่ส่งเข้าไป จึงไม่ควรนำ accuracy/confusion matrix จาก Test ไปเรียกว่าผลที่ threshold เลือกจาก Dev; Test EER เองคำนวณจากคะแนน Test ได้ตามนิยาม แต่ threshold นั้นไม่ใช้เลือกโมเดล
- ตัวประเมินปัจจุบันต้องมีสอง label จึงต้องเพิ่มการประเมิน FRR สำหรับชุดเสียงจริงล้วน
- AASIST และ RawNet2 ใช้ตัวโหลดเสียง/ตัว resample คนละทาง ต้องกำหนด preprocessing ร่วมก่อนเทียบชุดเสริมที่ sample rate ต่างจาก SEA-Spoof
- กำหนด score สูง = สนับสนุน bonafide; threshold แยกตามโมเดลและ protocol ไม่เทียบค่าคะแนนดิบข้ามโมเดล

แบ่งงาน: ผู้ทำ AASIST รับผิดชอบโมเดล AASIST; ผู้ทำ RawNet2 รับผิดชอบ RawNet2; metadata, manifest, การสร้างเสียงโทรศัพท์ และ metrics ใช้ส่วนกลางเดียวกัน ก่อนรันจริงตรวจไฟล์ตัวอย่างเดียวกันว่ามีความยาว/label/split ตรงกัน

## 7. เรื่องที่ต้องตกลงกับอาจารย์

1. อายุ/เพศ/ถิ่นต้องมีครบทุกไฟล์ของชุดหลัก หรือยอมรับการทดสอบเสริมที่มี metadata พร้อมการระบุข้อจำกัดของชุดหลัก?
2. คำว่า “ถิ่น” หมายถึงภูมิลำเนา ที่อาศัย หรือสำเนียง/ภาษาที่พูด?
3. ต้องครอบคลุมผู้สูงอายุและทุกภูมิภาคหรือไม่? ถ้าต้องครอบคลุม ให้กำหนดเป้าหมายจำนวนผู้พูดและความแม่นยำของการประมาณผลก่อนเก็บเพิ่ม
4. ยอมรับการวิเคราะห์ FRR รายกลุ่มบนเสียงจริงเป็นงานเสริมได้หรือจำเป็นต้องมีเสียงปลอมรายกลุ่มด้วย?
